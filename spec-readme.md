# Pipeline-Skills — Спецификация pipeline-скиллов

## Структура подпапок

```
spec-pipeline-skills/
├── root-spec-<skill-name>/
│   └── spec-<skill-name>_<variant>/
│       └── SKILL.md
├── README.md
```

### `root-*` — корневая папка вариации скилла

Каждая **корневая папка** (`root-spec-<skill-name>`) содержит разные вариации одного и того же
скилла. Вариация обозначается суффиксом после нижнего подчёркивания в имени папки:
`spec-<skill-name>_<variant>`. Пример: `root-spec-increment-actualize/` содержит папки
`spec-increment-actualize_default`, `spec-increment-actualize_custom`, и т.д.

### `default` — вариация по умолчанию

Вариация `default` — это базовый вариант скилла. Если у корневой папки только одна вариация и
она называется `default`, она считается единственным вариантом скилла.

Все скиллы в папках `root-*` с разными вариациями, но **одинаковым тегом запуска** (команда
`/spec-increment-*` или `/spec-absolut-init`) **запускаются одной и той же командой**, **принимают на вход
одинаковый набор аргументов** и **выдают на выходе одинаковый по смыслу результат** — но
**имеют разную реализацию** (например, разный формат выходного файла, разную детализацию
плана, разные фреймворки для тестов).

Таким образом, выбор вариации — это не выбор другого скилла, а настройка поведения одного
и того же скилла под конкретные нужды проекта.
