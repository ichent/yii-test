```markdown
|-------|-------------|----------------|---------------------|

## Cross-imports (`@x`)

| Слайс-владелец | Публичный API | Слайс-потребитель | Что экспортируется |
|----------------|---------------|-------------------|--------------------|

## Нарушения правил импорта

| Файл | Импорт | Нарушенное правило |
```

**Правила извлечения:**
- Собери все слайсы функциональности со всех слоёв: один бизнес-домен в FSD обычно размазан по `entities/`, `features/`, `widgets/`, `pages/`.

- Cross-imports ищи по каталогам `@x` и импортам вида `entities/A/@x/B`.
- Нарушения правил импорта: импорт из слоя выше, импорт соседнего слайса того же слоя минуя `@x`, импорт в обход публичного API напрямую во внутренний файл. Если в проекте настроен Steiger — сверься с его конфигом и правилами. Если правила зафиксированы в архитектурном документе проекта — сверяйся с ними и ссылайся на документ, а не пересказывай его.
- Слой `shared` в состав функциональности не включай: он общий. Исключение — слайсы `shared`, созданные исключительно под эту функциональность.

# Раздел `shell/` — микрофронтендная топология

Создаётся **только в микрофронтендных проектах** и только один раз на проект. Описывает контракт оболочки, общий для всех функциональностей: какое приложение отвечает за какие роуты, какие зависимости общие, как приложения обмениваются данными, как собираются.

Это единственный раздел, который не является бизнес-функциональностью. В корневом `index.md` он идёт первым.

## → `shell/index.md`

```markdown
# Оболочка (root-config)

[← Назад](../index.md)

## Описание
[Что за оболочка: single-spa root-config / Module Federation host; какой загрузчик модулей]

| Параметр | Значение |
|----------|----------|
| Фреймворк оболочки | [single-spa / Module Federation / ...] |
| Загрузчик модулей | [SystemJS + import maps / Module Federation / script-теги] |
| Файл root-config | [путь] |
| Файл import map | [путь или URL источника] |
| Оверрайды | [import-map-overrides: включены / нет] |

## Файлы

- [Приложения](applications.md) — registerApplication, activeWhen, customProps
- [Общие зависимости](shared-dependencies.md) — import map, externals, shared
- [Обмен данными](communication.md) — транспорт и реестр событий

```

```markdown
# Оболочка — Приложения

[← Назад](index.md)

## Зарегистрированные приложения

| name | activeWhen | Entry (import map) | Тип | Раздел спецификации |
|------|-----------|--------------------|-----|---------------------|

> **Источник:** [путь к root-config]

## Карта маршрутов уровня оболочки

| Префикс роута | Приложение | Пересечения с другими приложениями |
|---------------|-----------|-----------------------------------|

## customProps

| Prop | Тип | Кому передаётся | Источник значения |
|------|-----|-----------------|-------------------|

> Значения секретов не включать — только имена и назначение.

## Утилитные модули

| Модуль | Импорт | Назначение | Кто потребляет |
|--------|--------|------------|----------------|

## Layout / порядок монтирования

- [single-spa-layout, если используется: routes-конфиг, DOM-контейнеры]
- [порядок и вложенность приложений на общих экранах]
```

**Правила извлечения:**
- Читай root-config: все вызовы `registerApplication` (объектная и позиционная формы), значения `activeWhen`, `customProps`.
- `activeWhen` может быть строкой, массивом или функцией — фиксируй как есть, функцию описывай условием.
- В колонке «Раздел спецификации» ставь ссылку на бизнес-раздел, который живёт в этом приложении. Если приложение обслуживает несколько разделов — перечисли все.
- Если используется `single-spa-layout` — документируй layout-конфиг и DOM-контейнеры.
- Приложения из внешних репозиториев, код которых недоступен, помечай «внешний MFE» и документируй только по контракту import map и customProps.

```markdown
# Оболочка — Общие зависимости

## Стратегия

| Импорт | URL / источник | Версия | Кто потребляет |
|--------|----------------|--------|----------------|

> **Источник:** [путь к файлу import map]

## Externals приложений

| Приложение | Externals | Следствие |
|-----------|-----------|-----------|

## Module Federation (если используется)

| Параметр | Значение |
|----------|----------|
| Роль | [host / remote] |
| name | |
| remotes | |
| exposes | |
| shared (+ singleton / requiredVersion) | |

## Риски версий

| Зависимость | Ожидаемая версия | Где расходится | Последствие |
|-------------|------------------|----------------|-------------|
```

**Правила извлечения:**
- Сопоставь `externals` в webpack-конфигах приложений с записями import map: каждый external обязан иметь запись, иначе это дефект — зафиксируй его.
- Для Module Federation читай `ModuleFederationPlugin`: `name`, `remotes`, `exposes`, `shared`, флаги `singleton` и `requiredVersion`.
- Фиксируй библиотеки, требующие единственного экземпляра (React, роутер, стор, RxJS) и то, как это обеспечено.
- Расхождения версий одной библиотеки между приложениями выноси в «Риски версий».

```markdown
# Оболочка — Обмен данными между приложениями

[← Назад](index.md)

## Транспорты

| Транспорт | Механизм | Где реализован | Что передаётся |
|-----------|----------|----------------|----------------|

## Реестр событий

| Событие | Публикует | Слушает | Payload | Раздел-владелец |
|---------|-----------|---------|---------|-----------------|

> Подробности по каждому событию — в `microfrontend.md` раздела-владельца.

## Общее состояние

| Что | Механизм | Владелец | Потребители |
|-----|----------|----------|-------------|

## Общая навигация

| Механизм | Использование |
|----------|---------------|
| [navigateToUrl / history / router-события] | [как приложения переводят пользователя в чужие роуты] |
```

**Правила извлечения:**
- Ищи транспорты: `CustomEvent` / `window.addEventListener`, общий event bus в utility-модуле, RxJS-субъекты в shared-библиотеке, `customProps`-колбэки, `postMessage`, общий стор.
- Реестр событий — это таблица-индекс: имя, участники и ссылка на раздел-владелец, без дублирования подробностей.
- Фиксируй, как приложения переходят в роуты чужих приложений (`navigateToUrl`, history API).
- Отмечай неявные связи через `window` — для агента это скрытые зависимости, их важно назвать.

```markdown
# Оболочка — Сборка

## Разрешение импортов

| Алиас | Куда указывает | Где объявлен |
|-------|----------------|--------------|

> Алиасы из `resolve.alias` и `paths` в tsconfig. Нужны для трассировки импортов при чтении кода.

## Переменные окружения сборки

| Переменная | Где объявлена | На что влияет |
|-----------|---------------|---------------|

> Только имена и назначение, без значений.

## Плагины, влияющие на интеграцию

| Плагин | Назначение |
|--------|------------|
| [SystemJSPublicPathWebpackPlugin / ModuleFederationPlugin / ...] | |
```

**Правила извлечения:**
- Читай все webpack-конфиги проекта, включая обёртки (`webpack-config-single-spa`, `single-spa-angular/lib/webpack`, `webpack-merge`).
- `output.libraryTarget: "system"` и настройка publicPath — ключевые факты интеграции, фиксируй их явно.

- Значения переменных окружения и секреты не включать — только имена.
